RECOMENDACIONES PARA PUBLICAR EL TRACK DE INSTRUQT

Track: asp-foundations
Imagen: mongodb-ts-dev/asp-foundations-cli-v1
Host: workstation

1. Preparar la imagen
Crear una imagen Ubuntu 22.04 o 24.04 que cumpla los requisitos de Instruqt.
Instalar Atlas CLI, mongosh y jq usando instruqt/image/prepare-host. No instalar
Docker, no iniciar servicios y no guardar credenciales Atlas en la imagen.

2. Validar el runtime
Desde la raiz del repositorio ejecutar:

  node --test instruqt/image/test-runtime.mjs
  bash instruqt/image/package-runtime /ruta/absoluta/fuera/del/repo/asp-runtime-v1.tar.gz
  tar -tzf /ruta/absoluta/fuera/del/repo/asp-runtime-v1.tar.gz

Transferir el paquete de preparacion al builder por el mecanismo privado
aprobado y ejecutar image/prepare-host como root solo en ese builder desechable. Revisar los
requisitos de guest environment y machine identity de Instruqt antes de guardar
la imagen.

El setup de la track descarga por HTTPS los archivos runtime permitidos desde el
commit publico fijado en setup-workstation. Actualizar ese SHA cuando se publique
una revision revisada del runtime.

3. Publicar y probar
Desde instruqt/tracks/asp-foundations:

  instruqt track validate
  instruqt track push
  time instruqt track test

No usar --force. El test automatico simula el aprovisionamiento de Lab 00; hacer
ademas una prueba real con un proyecto Atlas dedicado y limpiar solo los
recursos creados para esa prueba. No habilitar hot starts hasta medir el flujo
completo.

4. Seguridad y operacion
Mantener las URIs Atlas en el archivo temporal por sandbox. No copiar .env,
secretos, perfiles Atlas ni datos de alumnos al repositorio o a la imagen.
La track no necesita Docker, Kafka, certificados TLS de sandbox ni ingress.
El sandbox necesita salida HTTPS a GitHub para descargar el runtime publico.
Los recursos Atlas no se borran automaticamente al terminar el sandbox.

Documentacion completa: instruqt/image/README.md.
